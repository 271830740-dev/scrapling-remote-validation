# Scrapling remote parser validation

Public synthetic fixtures only. This repository performs an offline parser check of Scrapling 0.4.15 on a GitHub-hosted Ubuntu runner. It does not contact travel websites, collect hotel prices, solve challenges, or use account credentials. No crawling or parser test runs on the operator's computer.

Run the `Offline parser validation` workflow manually. It pins the script's exact commit, records the GitHub run/job identity and runner environment, installs only the parser distribution from PyPI, and publishes its raw result and hashes as a one-day artifact. A passed check proves only the covered synthetic parser behavior, not production data quality or platform access.

`guarded_extraction.py` additionally rejects ambiguous cards, conflicting source supplier/hotel/room/rate IDs, duplicate prices, unknown or conflicting currencies and malformed amounts. `remote_quote_guard_check.py` checks these failure cases against fictional HTML on the same remote runner. Its data attributes are a synthetic source contract, not a travel-site adapter. Even a valid extracted amount explicitly remains a candidate requiring complete request, stay, guests, meals, cancellation, final-price, fee, eligibility, freshness and original-source verification.

`quote_json.py` guards bounded raw UTF-8 JSON before schema validation. It rejects repeated decoded object keys, invalid numeric constants and malformed input, and retains decimal precision without silently rounding prices. It preserves nulls and text IDs; numeric IDs still require explicit business validation. `remote_json_check.py` runs only on GitHub-hosted runners. This transport guard neither calls a website nor interprets any supplier price unit, tax rule or final payable amount.

`quote_comparison.py` compares explicitly source-normalized conditions, then computes the exact difference between same-currency, full-stay customer totals. Platform IDs, raw requests and price/fee amounts may differ. Physical room, requested stay/guests, actual meal schedule, payment timing, audience/market/device and complete absolute cancellation intervals must match. Fixed, percentage and first-night penalties retain distinct semantics. Source verification flags and evidence references are caller assertions, requiring independent authentication; a matched result remains a candidate and never accepts a real quote. Freshness and skew limits are required caller parameters. The fictional checks run remotely in `remote_comparison_check.py`; no actual supplier or website adapter is supplied.

Meals require an explicit verified room-only state or a nonempty verified schedule of actual service dates. Checkout breakfast and checkin dinner are valid; this contract does not infer one meal per night. Adapters must establish the full schedule and guest applicability, and consolidate guest-group entries only with source evidence; duplicate meal keys are rejected. Supported cancellation bases are full-stay customer total for fixed/percent penalties and a verified nightly customer-total schedule for first-night penalties; relative-time anchors and provider enums remain adapter responsibilities. Unknown price fields are rejected. An optional room/tax/mandatory-fee breakdown must sum exactly to the same-currency total, but its absence leaves charge completeness as an unauthenticated source assertion. Negative discounts and other component types require a future explicit contract rather than silent interpretation.
